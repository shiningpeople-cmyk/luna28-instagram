# LUNA28 Instagram 自動投稿

毎日のストーリーズ（ランキング→ひとこと→プロフィールへ）、週のリール・カルーセルを、
Googleスプレッドシートの予定表どおりに自動生成・自動投稿します。
画像・動画・音源はすべてプログラムで描画／合成（AI画像生成なし、メタデータなし）。

```
render/   動画・画像の生成（luna_video.py = エンジン, render_story / render_reel / render_carousel）
content/  リール・カルーセルの原稿JSON（予定表の「原稿キー」= ファイル名）
media/    生成したファイル（自動で git push され、公開URLになる）
run.py    毎日のランナー   publish.py  Instagram API   sheet.py  予定表の読み書き
check_setup.py  設定確認   tests/mock_graph.py  偽API   .github/workflows/post.yml  毎日 06:40 / 11:40 / 19:40 JST に起動
```

## 仕組み（承認してから投稿）
1. GitHub Actions が 06:40・11:40・19:40（JST）に起動（投稿時刻は 7:00・12:00・20:00 の3枠）
2. **準備**：7日以内の予定行の動画・画像を先に生成し、公開用ブランチ `media` に置いて、予定表の「プレビュー」列にURL、「状態」を「確認待ち」にする
3. **承認**：プレビューを開いて中身を見て、「承認(OK)」列に OK を入れる（NG なら直して状態を空に戻すと作り直す）
4. **投稿**：OK がある行だけ、予定時刻（2時間前〜40分後の窓）に Instagram へ投稿 → 「投稿済み」と投稿URLを書く
5. OK が無いまま予定を2時間過ぎた行は「見送り」にして通知（投稿されない）
6. アプリから手動で投稿したものには一切触りません。飯田さんのシート・仕組みにも触りません

## 予定表（Googleスプレッドシート）
タブ `予定表`

| A 日付 | B 時刻 | C 種類 | … | H 原稿キー | I キャプション | J 状態 | K 投稿URL | L 処理ログ | M メディアURL | N 承認(OK) | O プレビュー |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 2026/12/01 | 12:00 | カルーセル | | zukan_luna01 | （空なら自動で入る） | 確認待ち | | | | OK | （URLが自動で入る） |
| 2026/12/04 | 20:00 | リール | | reel_luna01 | | | | | | | |

- 種類は `ストーリーズ` `リール` `カルーセル` の3つ
- 状態：空＝これから準備 → `確認待ち`（プレビューあり）→ `予約` → `投稿済み`。`停止` にすると飛ばす。作り直したいときは状態を空に戻す
- 承認(OK)：プレビューを見て OK を入れた行だけ投稿される。予定の前日までに入れる
- タブ `設定`：`ig_user_id` / `access_token` / `token_updated` / `media_base_url`（空でよい）

## セットアップ（1回だけ・約30分）

### 1. Instagram API（Meta for Developers）— ✅ 2026/11/04 設定済み
- アプリ「LUNA28 Auto」（アプリID 1174301045550143）、ユースケース「Instagramでメッセージとコンテンツを管理」
- ユースケース → カスタマイズ → 「2. アクセストークンを生成する」で @luna28.japan を追加 → トークンを生成
- 取得したトークン（EAA… で始まる、無期限のシステムユーザートークン）と InstagramアカウントID **17841423104125573** は予定表の `設定` タブに記入済み
- EAA… のトークンは graph.facebook.com 経由で使い、延長は不要（プログラムが自動判定）。IG… で始まる60日トークンを入れた場合は graph.instagram.com 経由・7日ごと自動延長
- 自分のアカウントに投稿するだけなのでアプリレビュー不要（開発モードのままでOK）

### 2. Google（シートをプログラムに読ませる）
1. https://console.cloud.google.com/ → プロジェクト作成（名前は何でも）
2. 「APIとサービス」→「ライブラリ」→ **Google Sheets API** を有効化
3. 「認証情報」→「認証情報を作成」→ **サービスアカウント** → 作成後「キー」タブ → **鍵を追加 → JSON** → ダウンロード
4. 予定表スプレッドシートの「共有」に、JSON内の `client_email`（…@….iam.gserviceaccount.com）を **編集者** で追加

### 3. GitHub
1. https://github.com/ でアカウント（無料）→ **New repository** → 名前 `luna28-instagram`、**Public**（メディアを公開URLにするため）
2. このフォルダの中身をすべてアップロード（Add file → Upload files でフォルダごとドラッグ）
3. リポジトリの **Settings → Secrets and variables → Actions** に
   - Secret `GOOGLE_SA_JSON`：手順2でダウンロードしたJSONの中身を全部貼る
   - Secret `SHEET_ID`：予定表URLの `/d/` と `/edit` の間の文字列
4. 予定表の `設定` タブの `access_token` / `ig_user_id` は記入済み（手順1）
5. **Actions** タブ → 「LUNA28 Instagram 自動投稿」→ **Run workflow** → dry_run に `1` → 実行。緑になれば生成まで成功
6. 予定表に今から1時間以内のテスト行（ストーリーズ）を入れて、dry_run `0` で Run workflow → 実際に投稿されることを確認

以後は **翌月の行を入れておき、準備ができた行（確認待ち）のプレビューを見て OK を入れるだけ**。

## 毎月の運用
- ストーリーズ：日付・時刻 7:00・1位〜3位・ひとこと（31行）。ルナツールの出力を貼る
- カルーセル／リール：原稿JSONを `content/` に追加して、予定表に原稿キーを書く（原稿は松島側で用意、JSON化はClaudeで）
- 予定表の行が「確認待ち」になったらプレビューを見て「承認(OK)」に OK

## トラブル時
- Actions が赤になると GitHub から登録メールに通知が届く。予定表の L 列に理由が書かれる
- 「トークン無効」→ 手順1-4 をやり直して `設定` タブの `access_token` を貼り替える
- 原稿JSONに「【要原稿】」「【○】」が残っている行は投稿されず「失敗」になる（未確定の内容を出さないための安全装置）
- `ig_user_id` は毎回 API から取り直すので、シートの表示が 1.78E+16 のように丸まっていても問題ない
- 投稿は 24時間に 100件まで（API制限）。通常は1日2〜3件なので問題なし
- ストーリーズにはAPIからリンクスタンプを付けられない仕様のため、動画内の「プロフィールのリンクから」で誘導している

## 動作確認のしかた（本番前）
- `python3 tests/mock_graph.py 8765` で Instagram API の偽サーバーを立て、`IG_API_HOST=http://127.0.0.1:8765` を付けて `python3 run.py` を動かすと、投稿せずに全工程（生成→コンテナ→公開→書き戻し）を通せる
- GitHub Actions では「Run workflow」の dry_run=1 で生成までを確認してから、dry_run=0 でテスト行1本を実投稿する
- 失敗した行は予定表の状態が「失敗」になり、Actions も赤になって登録メールに通知が届く（成功時は通知なし）

## メディアのURLについて
- 既定では `raw.githubusercontent.com/<owner>/<repo>/media/media/...`（公開用ブランチ media）を Instagram に渡す（公開リポジトリが前提）
- もし処理ログに「メディアを取得できない」系のエラーが出たら、リポジトリの Settings → Pages で「Deploy from a branch / main / (root)」を有効にし、Actions の Variables に `MEDIA_BASE_URL = https://<owner>.github.io/<repo>` を追加する
